# Keymap behavior source audit

Source audit for roadmap item 8. It records existing behavior and gaps for the
requested semantics; it does not allocate keys or settle policy.

## Existing behavior and gaps

| Requested behavior | Existing source | Audit |
| --- | --- | --- |
| `dc`: compare pasted partial/full hash to selected object, for whole commit and historical file | `pkg/gui/controllers/historical_diff_actions.go`: `runHistoricalRevisionDiff`; `pkg/commands/git_commands/historical_diff.go`: `ResolveHistoricalDiffCommit`, `HistoricalRevisionDiffCmdObj` | The historical revision diff backend already resolves a full commit OID and builds the diff command used for whole commits and historical files. Accepting pasted hash text and resolving it unambiguously as a separate comparison endpoint is absent; the current UI passes the selected full OID. |
| Global Enter creates a commit using `WorkingTreeHelper.HandleCommitPress` | `pkg/gui/controllers/files_controller.go`: `commit.create`; `pkg/gui/controllers/main_view_controller.go`: commit action binding; `pkg/gui/controllers/helpers/working_tree_helper.go`: `HandleCommitPress` | The handler is registered in Files and in the main/secondary diff controllers through `workingTreeAction`, which limits it to working-tree mode. Global availability from every normal pane is absent. The user confirmed that dialogs/search/editors retain normal Enter behavior. |
| F5 refreshes full repository model and rerenders every pane, without fetch | `pkg/gui/controllers/global_controller.go`: `app.refresh` → `GlobalController.refresh`; `pkg/gui/controllers/helpers/refresh_helper.go`; `pkg/gui/types/refresh.go`: empty `RefreshOptions.Scope` refreshes all views; `pkg/gui/main_panels.go`; `pkg/gui/background.go` | A full-model refresh path exists and is distinct from fetch. Current refresh binding is `Universal.Refresh`; no F5-specific binding/contract explicitly couples full refresh with rerendering all panes. Fetch is a separate background operation. |
| `x` always confirms discard, ignoring skip-warning config | `pkg/gui/controllers/workspace_reset_controller.go`: `FilesController.createResetMenu`, `worktree.discard-all`; `pkg/gui/controllers/working_tree_diff_actions.go`; `pkg/config/user_config.go`: `Gui.SkipDiscardChangeWarning` | The discard-all menu action calls `Confirm` unconditionally. Other discard actions use `ConfirmIf` with `SkipDiscardChangeWarning`. The requested unconditional behavior is not consistently attached to one `x` command across the relevant views. |
| `r` rebase and `m` merge show informative confirmations using captured targets | `pkg/gui/controllers/helpers/captured_rebase.go`; `pkg/gui/controllers/helpers/captured_merge.go`; `pkg/gui/controllers/branches_controller.go`: `branch.rebase-current-onto-selected`, `branch.merge-selected-into-current`; `pkg/gui/controllers/branch_sync_bindings.go`; `pkg/gui/controllers/selected_commit_rebase_actions.go` | Selected-source rebase and merge flows capture source/repository and review the operation before execution. Commit-list selected-target rebase also captures its selected OID. Existing actions are split by source/target context; there is no unified `r`/`m` key registration or common confirmation presentation across them. Rename handlers are unrelated to these requested meanings. |
| `sh` / `sm` / `ss`: direct reset mode preselected, current HEAD and selected OID | `pkg/gui/controllers/basic_commits_controller.go`: `branch.reset-menu`; `pkg/gui/controllers/helpers/captured_reset.go`; `pkg/gui/controllers/workspace_reset_controller.go` | Selected-commit reset currently opens a reset-mode menu and captures the target. The files-pane mode menu resets relative to `HEAD`. No three direct selected-commit reset bindings with mode preselected were found. |
| `sc`: choose branch/commit checkout; new-name/move non-current branch; carry dirty changes except collisions | `pkg/gui/controllers/basic_commits_controller.go`: `commit.checkout-menu`; `pkg/gui/controllers/helpers/named_checkout.go`; `pkg/gui/controllers/helpers/refs_helper.go`; `pkg/gui/controllers/branches_controller.go`; `pkg/commands/git_commands/named_checkout.go` | Named checkout supports creating, attaching, or moving a branch to the selected commit and carries safe dirty changes while refusing collisions. Branch checkout and commit checkout remain separate controller flows; a combined chooser on `sc` is absent. |
| `nb`: create a named branch or move an existing named non-current branch to the selected source, without checkout | `pkg/gui/controllers/branch_placement_actions.go`: `branch.place-at-selected-commit`; `pkg/commands/git_commands/branch_placement.go`; `pkg/commands/git_commands/branch_placement_guard.go` | Ref-only create/move at a selected commit exists and does not checkout. It is currently a commit-list flow. The requested source may also be a selected branch. Existing non-current/unoccupied branch constraints continue to apply; no extra “same source” restriction is implied. |
| `cy`: idempotently mark selected commits | `pkg/gui/controllers/helpers/cherry_pick_helper.go`: `CopyRange`; cherry-picking mode | Current copy-range behavior toggles: if every selected commit is already copied, it removes them. Mark-only idempotent behavior is absent. |
| `cx`: unmark selected commits only, never clear all | `pkg/gui/controllers/basic_commits_controller.go`: `commit.clear-cherry-pick-selection`; `pkg/gui/controllers/helpers/cherry_pick_helper.go`: `Reset`, `CopyRange` | Existing reset clears the complete copied selection. Range toggle can remove commits only when all selected commits are already marked. A dedicated selected-only unmark action is absent. |
| `cp`: paste marked commits or selected commits, confirm exact list, retain captured order and HEAD | `pkg/gui/controllers/local_commits_controller.go`: `commit.cherry-pick`; `pkg/gui/controllers/helpers/cherry_pick_helper.go`: `Paste`; `pkg/gui/modes/cherrypicking/` | Paste currently uses the copied commit list and confirms only the count. It does not show the exact commit list or captured destination HEAD, and has no selected-commits fallback. The flow currently autostashes tracked working-tree dirt before cherry-pick and pops afterward (`CherryPickHelper.Paste`); the new flow must remove this implicit stash behavior and report native Git precondition failures. Any stale-target guard should follow the fork's captured-flow check-then-run pattern, not assume locks or special concurrency guarantees. |

## Resolved scope and review boundary

The user confirmed global Enter means commit creation from every normal pane;
Enter in dialogs, search and editors keeps its normal confirm/input behavior.
The latest key table and [allocation proposal](keymap-allocation.md) define the
requested behavior and proposed marked/selected cherry-pick source review.
The final bindings and behavior changes remain unimplemented pending user
review. No application files or tests were changed by this source audit.
